# AGENTS.md — Polemica Notes

Справочник для ИИ-агентов и людей, работающих с этим кодом. Прочитай целиком,
прежде чем менять код: половина файла — это дорого купленные уроки четырёх
больших аудитов (v8.1.21–8.1.24, июль 2026), и нарушение любого инварианта из
раздела 4 с высокой вероятностью вернёт уже починенный класс багов.

## 1. Что это

Браузерное расширение (Chrome + Firefox, Manifest V3) для polemicagame.com —
онлайн-версии спортивной мафии. Возможности: заметки об игроках со статистикой,
метки «мой read» по ролям, статистика разбора матча, автопринятие игры,
интеграция с OBS Studio (переключение сцен день/ночь, скрытие роли для стрима),
Twitch-чат поверх игры, хоткеи.

- Юзербаза маленькая, но живая; данные пользователей (заметки) — главная
  ценность, их потеря недопустима.
- `legacy/` — старая JS-версия до TypeScript-рефакторинга. НЕ собирается и НЕ
  правится; используется только как справка по прежнему поведению и форматам
  данных. Там же лежит `legacy/match_314446.json` — **настоящий JSON матча**,
  единственный источник правды о форме данных API (см. раздел 5).

## 2. Сборка и релиз

```bash
npm run typecheck        # tsc --noEmit — обязан быть чистым
npm run build            # оба таргета: dist/chrome и dist/firefox
npx web-ext lint -s dist/firefox   # 0 errors; ~22 warnings (innerHTML) — норма
```

- Один JS-бандл (tsup, iife, без минификации) на оба браузера; различия только
  в манифесте (`src/manifest/manifest.base.json` + overlay chrome/firefox,
  сборка `scripts/assemble.mjs`).
- Версию надо поднимать в ДВУХ местах: `package.json` и
  `src/manifest/manifest.base.json` (автосинка нет).
- Релиз: commit → push → zip обоих dist → `gh release create vX.Y.Z` с
  русскими release notes и обоими zip. Тегов локально нет — тег создаёт gh.
- Минимальные версии: Chrome 116 (`minimum_chrome_version`), Firefox 121
  (`strict_min_version`; поднято из-за `:has()` в инжектируемом CSS).

## 3. Архитектура

```
src/
  core/        — общий слой (дублируется в каждый бандл, состояние ПЕР-контекстное!)
    feature.ts       FeatureManager: enable/update/disable по настройкам,
                     очередь sync, откат disable() при упавшем enable()
    dom.ts           SharedDomObserver — ЕДИНСТВЕННЫЙ MutationObserver на документ
                     (childList+subtree+attributes class/style, rAF-батчинг,
                     буфер ≤4000, таймер-фолбэк в фоновой вкладке)
    settings.ts      storage.sync + LOCAL_KEYS (секреты → storage.local)
    notes-store.ts   заметки в storage.local + разовая миграция из sync
    keyboard.ts      единый keydown-роутер: event.code, typing-context,
                     модификаторы, e.repeat
    log.ts           кольцевой буфер → storage.local (ключ на контекст),
                     prime при старте, pagehide-флеш
    messaging.ts, errors.ts, escape.ts, selectors.ts, FloatingPanel.ts
  content/     — content-скрипт: index.ts (регистрация фич), фичи, панели
  background/  — SW (Chrome) / event page (Firefox): OBS-клиент, инжект автопринятия
  popup/       — настройки: дифф-запись, подписка на onChanged
  shared/types.ts — Settings + ExtMessage (вся матрица сообщений)
```

Ключевые механики:
- **Фичи** регистрируются в `content/index.ts`; `settingKey: null` = фича
  активна всегда (auto-start, tooltip, obs-panel), гейты — внутри неё.
- **Сообщения**: popup ↔ background ↔ content через `core/messaging`.
  Полифилл доставляет ответ ТОЛЬКО если хендлер вернул Promise.
- **Три бандла из одних исходников**: модульные let-переменные core/*
  существуют отдельно в каждом контексте. Это не общее состояние!

## 4. Инварианты (нарушишь — вернёшь старые баги)

1. **Каждая запись в DOM из подписчика `onDomChange` обязана быть
   идемпотентной** (сравнение перед записью) или задросселенной. Общий
   наблюдатель следит за class/style/childList всего документа: безусловная
   запись = самоподдерживающийся цикл на частоте кадров = «сайт сходит с ума,
   лечится перезапуском браузера». Так было в 6+ местах до 8.1.21.
2. **Автоклики**: только точное совпадение нормализованного текста (никаких
   подстрок — «Не готов» содержит «готов»!), только видимые элементы, бюджет
   попыток, бэкофф 5с после trusted-действий пользователя, гейт по контейнеру
   контекста (точная «Подтвердить» есть в любом диалоге сайта). textContent
   наследуется вниз — фильтр по тексту без deepest-only дедупа матчит
   родителя И дитя.
3. **Заметки живут в storage.local** — осознанное решение владельца (sync
   имеет лимит 8 КБ/ключ и молча терял заметки). НЕ возвращать в sync без
   нового решения. `obs_password` — только storage.local (`LOCAL_KEYS`).
4. **Попап пишет только дифф** против `lastKnown` и подписан на onChanged.
   Никогда не писать весь объект настроек снимком DOM.
5. **Хоткеи**: `event.code` (раскладко-независимо: KeyF = «а»!), обязательные
   гейты typing-context / модификаторы / repeat — и в роутере, И в любом
   отдельном listener'e (как dBlocker в role-faker).
6. **WebSocket-переподключение**: перед заменой сокета отвязать ВСЕ четыре
   хендлера старого (включая onopen!) и сделать полный teardown состояния
   (isConnected и пр.), иначе — залипшие статусы и вечный connecting.
7. **Симметрия жизненного цикла**: всё, что навесил enable(), снимает
   disable() — та же ссылка, тот же capture-флаг; хвостовые setTimeout —
   в именованных переменных и тоже гасятся.
8. **Формы данных матча** сверять с `legacy/match_314446.json`, а не с
   предположениями. Известное: `data.{players,votes,shots,checks}`; туры
   голосования `num: 0` (основной) / `1` (переголосовка) / `2` (подъём всех);
   роли: 0=дон, 1=мафия, 2=мирный, 3=шериф; `firstKilled` — это userId,
   НЕ позиция; guess бывает у нескольких игроков.
9. **Миграции storage** — атомарно (данные+флаг одним `set`), флаг
   per-device в local, sync-копию заметок не удалять (мост для вторых
   устройств). Разовые чистки — в `runUpgradeMigrations()`
   (background/index.ts) под собственным флагом.
10. При «оживлении» настройки, которую старый попап писал, но никто не
    читал, — обязательна разовая миграция: у всех активных пользователей в
    storage лежит бессмысленное старое значение (кейс
    twitch_floating_panel_enabled, 8.1.23→8.1.24).

## 6. Техдолг (актуален на v8.1.24)

Отсортировано по (вред × вероятность). Файл:строка проверены на HEAD.
Перед работой перепроверь — код живой.

### Высокий приоритет
1. ✅ ЗАКРЫТО в 8.1.25 (opencode + доводка): chrome.alarms-watchdog,
   reconcile при пробуждении SW, persisted-блоки со сбросом на onStartup.
   Остаток: patch history в SPA-роутере — мёртвый код в isolated world
   (реально работают polling 500мс + popstate), можно упростить.
2. ✅ ЗАКРЫТО в 8.1.25: единый URL-роутер (content/index.ts), route-sync у
   match-stats/player-notes, AbortController в match-data. Остаток:
   pendingGameData теряется, если Vue рендерит матч дольше 10с (give-up без
   ретрая) — узкое окно «нет статистики до F5» на медленной сети.
3. **Статистика «???» навсегда** для игрока вне активных игр (нет фолбэка
   через rating/get-list в loadPlayerStats) и молчаливая кнопка для игрока вне
   топ-1000 (limit=1000 без пагинации). Ядро главной фичи.
   → `player-notes.ts:~400-420, ~650, ~1095`.
4. **Заметки ключуются ником**: тёзки делят заметку, регистр/смена ника теряет
   её (ключ регистрозависим, кэши lowercase). player.id доступен, но не
   используется. Нужна схема id-ключей с миграцией. → `player-notes.ts`.

### Средний приоритет
5. Автомод OBS: детект день/ночь полностью русскоязычный (на EN-интерфейсе
   мёртв) + `findDeepestTextWith` читает textContent всего body до ~7 раз/с;
   characterData не наблюдается (in-place смена текста невидима).
   → `obs-panel.ts:~465-620`, `dom.ts` (observer config).
6. FloatingPanel: pointermove/pointerup не в cleanup — unmount во время drag
   оставляет window-слушатели, persistBox пишет нулевой бокс (панель
   «исчезает» в 0×0 до чистки localStorage); нет pointercancel; drag будит
   всех подписчиков observer'а покадрово. → `core/FloatingPanel.ts:~180-240`.
7. Тултипы-сироты (tooltip.ts): re-enter <100мс не гасит таймер и не удаляет
   предыдущий тултип — копятся в body с pointer-events. settingKey:null ⇒
   disable никогда. → `tooltip.ts:~300-350`.
8. camera-flip: вечный rAF-цикл при пересоздании плитки (dataset.flipped на
   отсоединённом video); при null-ctx canvas добавлен, opacity=0, второй клик
   даёт второй canvas; teardown при disable отсутствует. → `camera-flip.ts`.
9. Логи: две content-вкладки пишут в один ключ (last-writer-wins);
   `polemica:buflevel` управляется localStorage сайта — сайт может включить
   debug и собрать Twitch-чат в экспортируемый файл. → `log.ts:33-60`.
10. pause-hotkey: ensureMenuOpen перебирает кандидатов КЛИКАМИ (до 7с чужих
    меню, клик по `a` может увести со страницы); getPauseButton без isVisible;
    открытые меню не закрываются при неудаче; «Продолжить/Resume» не
    матчится для снятия паузы. → `pause-hotkey.ts:~100-230`.
11. XSS (мир страницы): `href="${base}#${roleId}"` в innerHTML истории игр
    без экранирования (base из DOM сайта, roleId из API).
    → `player-notes.ts:~1223`.
12. match-stats: точка «лучшего хода» по слабым условиям (fallback nights[0],
    сравнение со СТАРТОВЫМ числом мафии); колонки в порядке массива players
    без сортировки по position; 4 разные палитры цветов ролей между фичами
    («Черные» синим в ЛХ-тултипе). → `match-stats.ts:~380-480, 175-180, 589`.

### Низкий приоритет / решения владельца
13. Фоновый инжект автопринятия дублирует контентный — убрать вместе с
    permission "scripting"? (Осознанно оставлен как страховка.)
14. Дефолты новичка агрессивны: auto_accept/skip_start/debug_logging = true

15. Twitch «Подключено» в попапе — по setTimeout(2000) без подтверждения;

16. `version` пишется в local при каждом сохранении заметок, никем не
    читается (карго-культ от legacy). → `notes-store.ts:163`.
17. Полифилл webextension-polyfill забандлен ×3 (~97 КБ суммарно) — в MV3
    Chrome почти не нужен.
18. isTypingContext слеп к shadow DOM; Enter не в producesText;
    contenteditable="plaintext-only" в Chromium. → `keyboard.ts:23-39`.
19. Гонки узких окон: миграция заметок из двух контекстов одновременно;
    RMW-импорт всей карты; role-marker last-write-wins в окне дебаунса 400мс.
20. nickname-lengths считает кодовые точки, а сайт, вероятно, UTF-16-юниты.

## 7. Как аудитить этот проект

Проверенная методика (4 итерации, ~50 подтверждённых находок):

1. Запускай 5–7 узкоспециализированных субагентов ПАРАЛЛЕЛЬНО, каждому —
   свой срез (готовые промты: `docs/audit-prompts.md`).
2. Каждому агенту давай список УЖЕ ИЗВЕСТНЫХ находок («не повторяй») — иначе
   половина отчёта будет пересказом.
3. Требуй: файл:строка, конкретный сценарий пользователя, серьёзность, и
   ОБЯЗАТЕЛЬНО раздел «проверено и чисто» (отсутствие находок в области —
   тоже результат).
4. **Проверяй громкие находки сам, прежде чем чинить.** Агенты ошибаются:
   «рассинхрон формы payload» в match-stats был опровергнут реальным JSON
   (`legacy/match_314446.json`), а «XSS в баннере обновления» — чтением кода
   (там textContent). И наоборот: «аутентификация OBS не работала никогда»
   подтвердилась.
5. После каждой волны фиксов — отдельный агент на ревью СВЕЖЕГО диффа
   (регрессии находились в каждом релизе: acceptScanTimer, twitch onopen,
   завис connecting, регрессия twitch_floating_panel_enabled) и отдельный
   агент на «путь обновления» (что случится у живых пользователей со старым
   storage).
6. Сверка бэклога отдельным агентом: «проверь по коду, что из списка ещё
   открыто» — не верь списку на слово.
