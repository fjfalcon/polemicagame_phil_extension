# AGENTS.md — Polemica Notes

Справочник для ИИ-агентов и людей, работающих с этим кодом. Прочитай целиком,
прежде чем менять код: половина файла — это дорого купленные уроки четырёх
больших аудитов (v8.1.21–8.1.24, июль 2026), и нарушение любого инварианта из
раздела 4 с высокой вероятностью вернёт уже починенный класс багов.

## 1. Что это

Браузерное расширение (Chrome + Firefox, Manifest V3) для polemicagame.com —
онлайн-версии спортивной мафии. Возможности: заметки об игроках со статистикой,
метки «мой read» по ролям, статистика разбора матча, автопринятие игры,
интеграция с OBS Studio (переключение сцен день/ночь, скрытие роли для стрима),
Twitch-чат поверх игры, хоткеи.

- Юзербаза маленькая, но живая; данные пользователей (заметки) — главная
  ценность, их потеря недопустима.
- `legacy/` — старая JS-версия до TypeScript-рефакторинга. НЕ собирается и НЕ
  правится; используется только как справка по прежнему поведению и форматам
  данных. Там же лежит `legacy/match_314446.json` — **настоящий JSON матча**,
  единственный источник правды о форме данных API (см. раздел 5).

## 2. Сборка и релиз

```bash
npm run typecheck        # tsc --noEmit — обязан быть чистым
npm run build            # оба таргета: dist/chrome и dist/firefox
npx web-ext lint -s dist/firefox   # 0 errors; ~23 warnings (innerHTML) — норма
```

**Adversarial review обязателен после КАЖДОГО изменения кода** (правило
владельца, 01.08.2026): перед коммитом/релизом любой правки запускается
отдельный агент-ревьюер, которому даётся дифф, контекст задачи и явное
задание атаковать инварианты §4, сценарии пользователя и совместимость
браузеров. Находки чинятся, затем контрольный раунд у ТОГО ЖЕ ревьюера
(его контекст сохраняется — продолжать сессию, не спавнить нового) до
вердикта «К РЕЛИЗУ ГОТОВО». Многораундовость — норма: блокеры находились
и на 3–4-м раунде.

- Один JS-бандл (tsup, iife, **минифицированный** — включено перф-аудитом
  01.08.2026, находка 6: content.js грузится на каждой странице сайта, и
  ~449 КБ неминифицированного JS парсились до возврата управления; обфускации
  нет, это допустимо и для CWS, и для подписи AMO) на оба браузера; различия
  только в манифесте (`src/manifest/manifest.base.json` + overlay
  chrome/firefox, сборка `scripts/assemble.mjs`).
- Версию надо поднимать в ДВУХ местах: `package.json` и
  `src/manifest/manifest.base.json` (автосинка нет).
- Релиз: бамп версии → commit → push →
  `source ~/.config/polemica-notes/amo.env && npm run release:assets` →
  `gh release create vX.Y.Z <три файла> --title … -F -` с русскими release
  notes. Тегов локально нет — тег создаёт gh.
  `release:assets` делает typecheck + сборку + оба zip + **подпись .xpi**
  (обязательна с 8.1.56: без неё Firefox-пользователи получают установку,
  которая стирает их данные при закрытии браузера). Без ключей в окружении
  скрипт не молчит: говорит, что .xpi не собран, и выходит с кодом 1.
  Осознанный пропуск — `npm run release:assets -- --skip-sign`.
  ВАЖНО: одну версию AMO подписывает ОДИН раз («Version X already exists») —
  перевыпуск требует бампа.
- Минимальные версии: Chrome 116 (`minimum_chrome_version`), Firefox 121
  (`strict_min_version`; поднято из-за `:has()` в инжектируемом CSS).

## 2а. Тестовая сессия на живом сайте (браузер агента)

Иногда единственный способ понять поведение сайта — измерить его в игре
(так найдены `:game-data`, хеши иконок камеры, `backdrop-filter` на
`.player__info`). Владельцу НЕ нужно каждый раз это объяснять — процедура:

1. `preview_start {url: "https://polemicagame.com/game-search"}` — открыть
   панель браузера. Сессия часто слетевшая: **пароль вводит владелец сам**,
   агент пароли не вводит никогда.
2. Владелец создаёт лобби (можно одному) и говорит, что оно готово.
3. Панель браузера **блокирует камеру и микрофон** — сайт покажет «Ошибка
   подключения к камере или микрофону». Лечится подменой устройств через
   `javascript_tool` ДО клика «Попробовать снова»:
   - `canvas.captureStream(15)` + рисование в canvas по setInterval = видео;
   - `AudioContext` → `createMediaStreamDestination()` с `gain = 0` = звук;
   - переопределить `navigator.mediaDevices.getUserMedia` (возвращает
     `new MediaStream([...video, ...audio])`) и `enumerateDevices` (три
     фейковых устройства: videoinput / audioinput / audiooutput).
   Ставить через `Object.defineProperty(..., {configurable: true})`.
4. Патч живёт до перезагрузки страницы и **слетает при переходах**: после
   «Попробовать снова» проверить и при необходимости поставить заново
   (гард `window.__pnFake`), затем «Продолжить» → «Начать игру».
5. Дальше — измерения через `javascript_tool`: `getComputedStyle`,
   `getBoundingClientRect`, `document.elementsFromPoint` (что РЕАЛЬНО сверху).
   Проверять гипотезу, а не глазами по скриншоту.
6. **Убрать за собой**: все тестовые узлы вставлять с общим классом
   (`.pn-test*`) и удалить в конце — страница остаётся владельцу.

Расширение в этой панели не установлено, и бандл туда не инжектится (ему
нужны `chrome.*` API). Проверять надо МЕХАНИКУ (копию логики на голом JS),
а не сам код расширения.

### Почему НЕТ browser E2E с установленным расширением (решение 28.08.2026)

Внешнее арх-ревью предложило поднять Puppeteer с unpacked-расширением и
гонять смоук «попап открылся, content внедрился, тумблер выключает фичу».
Взвесили и отказались — осознанно, а не по лени:

- **Класс, который он ловит, у нас уже закрыт с трёх сторон.** «Собрали
  битый бандл» ловит `release:assets` (прод-typecheck + вся офлайн-сюита +
  `web-ext lint` + штамп с хэшами), «манифест разъехался» — инварианты
  (`architecture.test.ts`), «сайт сменил разметку» — `test:contract` по
  живому сайту. E2E добавил бы четвёртую проверку того же.
- **Он НЕ ловит то, от чего болело.** Обе прод-жалобы 9.28.x («кнопок
  нет», «чат не везде») — это значение в storage у КОНКРЕТНОГО
  пользователя и гейт маршрута. Смоук на чистом профиле проходит их обе.
- **Цена постоянная, а не разовая.** Живой Chromium в гейте — это ещё одна
  зависимость, флаки на CI-машине без GPU и правки при каждой смене
  разметки сайта. У проекта соло-мейнтейнер: гейт обязан быть быстрым
  (сейчас вся сюита — 6 секунд) и молчаливым, иначе его начнут пропускать.

**Что пересмотрит решение:** первый же случай, когда в релиз уехал бандл,
который не грузится в браузере, или сломанный попап. Тогда заводим ОДИН
смоук (загрузка unpacked → SW жив → попап рисуется), а не десять.

## 2б. Почему у пользователей слетают настройки (важно, не «баг»)

Разные причины в двух браузерах — обе про идентичность расширения:

- **Chrome/Chromium**: у распакованного расширения ID = хеш ПУТИ к папке.
  Распаковал новый релиз в другую папку (`polemica-chrome (2)`) — это для
  Chrome ДРУГОЕ расширение с пустым storage. Лечится либо распаковкой
  строго поверх той же папки, либо полем `key` в манифесте (фиксирует ID
  независимо от пути). Внимание: добавление `key` СМЕНИТ ID у тех, кто уже
  пользуется, и разово обнулит их данные — только с явного согласия
  владельца и с предупреждением в release notes.
- **Firefox**: временное дополнение (`about:debugging`) выгружается при
  закрытии браузера, и Firefox **удаляет его storage**. Лечится только
  постоянной установкой — подписью XPI через AMO. Для отладки помогает
  `about:config` → `keepStorageOnUninstall` и `keepUuidOnUninstall` = true.

### Подпись XPI (Firefox, unlisted)

```bash
source ~/.config/polemica-notes/amo.env   # ключи AMO, вне репозитория, chmod 600
npm run build && npm run sign:firefox     # → dist/signed/*.xpi
```

- Ключи (`WEB_EXT_API_KEY` / `WEB_EXT_API_SECRET`) в репозитории НЕ хранятся
  и в команды не вписываются — только через этот файл. `.gitignore` закрывает
  `.env*`, `*.pem`, `amo.env` на случай копии рядом с кодом.
- Канал `unlisted`: в каталоге AMO не публикуется, модерация автоматическая.
- Одну и ту же версию манифеста подписать дважды нельзя — сначала бамп.
- ПОРЯДОК: сначала `release:assets` (он пересобирает `dist` с нуля), и только
  потом подпись — иначе rimraf уносит уже скачанный `dist/signed/*.xpi`, а
  переподписать ту же версию AMO не даст (409). Если так вышло — файл лежит
  на AMO и качается по API версий (`filter=all_with_unlisted`).
- ID `polemica-notes@polemicagame` уже в `manifest.firefox.json` — он и
  закрепляется за аккаунтом на AMO.
- У пользователей временной установки данные на подписанную версию НЕ
  переедут: сначала экспорт бэкапа (8.1.56), потом импорт.

Пока это не решено — единственная страховка пользователя это экспорт/импорт
бэкапа в попапе (вкладка «Ещё»), и он обязан включать НЕ только заметки.

## 2в. Тесты

Автотесты разделены на быстрый офлайн-набор и живой контракт сайта:

```bash
npm test                 # unit/property + статические инварианты, без сети
npm run test:watch       # тот же набор в watch-режиме
npm run test:contract    # живые бандлы и HTTP API polemicagame.com
npx tsc --noEmit -p tests/tsconfig.json  # отдельная типизация тестов
```

- `tests/unit/` проверяет чистые функции, DOM-helper'ы и небольшие state machine;
  property-based проверки fast-check имеют фиксированные seed.
- `tests/invariants/` читает production-исходники и защищает правила §4:
  storage, lifecycle, Settings/defaults, permissions, единственный observer,
  dual-manifest, границу селекторов и единственных писателей заметок и
  палитры. Allowlist всегда узкий и с причиной; новый exception нельзя
  добавлять только ради зелёного теста.
  Критичные правила разбирают СИНТАКСИЧЕСКОЕ ДЕРЕВО (`typescript` API), а не
  текст: за август 2026 регулярка трижды оказывалась слабее собственного
  обещания — не видела классы в константах, дженерик-вызовы и «наш» класс,
  приписанный к списку чужих. Правило см. §4.
- `tests/contract/` — единственный сетевой набор. При отсутствии сети или 5xx
  он делает skip, а не fail. Исчезнувший selector/locale/API shape — fail.
- Кэш реальных фаз и ожидаемые SHA лежат в `tests/fixtures/`. Смена SHA сама по
  себе только печатает предупреждение. После ручной проверки нового сайта хеши
  обновляются командой
  `UPDATE_CONTRACT_FIXTURES=1 npm run test:contract`; получившийся diff fixture
  обязательно просмотреть перед коммитом.
- Если контракт покраснел, сначала отличить недоступность/авторизацию от
  реального drift, затем сверить новый bundle/API с потребителем. Не обновлять
  fixture так, чтобы он просто принял исчезнувший selector или неверную форму.
- `test.todo` обозначает подтверждённый или требующий решения production-баг.
  Его не удаляют и не превращают в бессодержательный pass: после фикса todo
  заменяется исполняемым регрессионным тестом.

Ключевые механики:
- **Фичи** регистрируются в `content/index.ts`; `settingKey: null` = фича
  активна всегда (auto-start, tooltip, obs-panel), гейты — внутри неё.
- **Сообщения**: popup ↔ background ↔ content через `core/messaging`.
  Полифилл доставляет ответ ТОЛЬКО если хендлер вернул Promise.
- **Три бандла из одних исходников**: модульные let-переменные core/*
  существуют отдельно в каждом контексте. Это не общее состояние!

## 4. Инварианты (нарушишь — вернёшь старые баги)

1. **Каждая запись в DOM из подписчика `onDomChange` обязана быть
   идемпотентной** (сравнение перед записью) или задросселенной. Общий
   наблюдатель следит за class/style/childList всего документа: безусловная
   запись = самоподдерживающийся цикл на частоте кадров = «сайт сходит с ума,
   лечится перезапуском браузера». Так было в 6+ местах до 8.1.21.
   С 9.33.1 инвариант ИСПОЛНЯЕМЫЙ: tests/invariants/dom-fixpoint.test.ts
   гоняет фичи через НАСТОЯЩИЙ SharedDomObserver до фикспоинта (новая
   DOM-пишущая фича обязана получить там сценарий), а рантайм-сторож в
   dom.ts пишет warn при минуте безостановочных проходов вне комнаты.
1а. **Селекторы сайта — только в `core/selectors.ts`.** Точнее: ЗАПРОСЫ к DOM
   ходят только через реестр (`SITE` — селекторы, `SITE_CLASS` — имена для
   `classList`), и это исполняемо. Но «при редизайне правится ОДИН файл» —
   неправда, и так было всегда: есть ещё CSS дистрибутива
   (`src/static/notes.css`, там же scoped-хеш Vue) и CSS-блоки внутри семи
   фич. Оба списка перечислены в инварианте поимённо и служат чек-листом:
   они отваливаются МОЛЧА, без исключения. Полный список — в шапке
   `selectors.ts`. Инвариант
   `architecture.test.ts` валит сборку на сыром классе сайта в любом другом
   файле. Наша собственная разметка (`pn-`, `fp-`, `ss-`, `twitch-`,
   `data-pn-*`) под правило не подпадает — это не знание о вёрстке чужого
   сайта; исключения для наших узлов с общими именами (`.row`, `.cell`,
   `.player-name`) перечислены в самом инварианте поимённо.

   Страж разбирает **синтаксическое дерево**, а не текст: `qs(".x")`,
   `qs<T>(".x")`, `el?.qs<T>(\n".x")` и строковая константа-селектор для него
   одно и то же. Регулярка этого не умела и дважды создавала ложное чувство
   полноты — сначала не видела классы в константах, потом дженерик-вызовы
   (внешний аудит 28.08.2026). **Правило для новых стражей: критичные
   архитектурные утверждения проверяются по AST или по поведению; регулярка
   годится как дешёвый детектор дыма, но не как доказательство.**

2. **Автоклики**: только точное совпадение нормализованного текста (никаких
   подстрок — «Не готов» содержит «готов»!), только видимые элементы, бюджет
   попыток, бэкофф после trusted-действий пользователя (auto-start — 5с;
   queue-requeue и postgame-search — 2с, принято ревью), гейт по контейнеру
   контекста (точная «Подтвердить» есть в любом диалоге сайта). textContent
   наследуется вниз — фильтр по тексту без deepest-only дедупа матчит
   родителя И дитя.
3. **Заметки живут в storage.local** — осознанное решение владельца (sync
   имеет лимит 8 КБ/ключ и молча терял заметки). НЕ возвращать в sync без
   нового решения. `obs_password` — только storage.local (`LOCAL_KEYS`).
4. **Попап пишет только дифф** против `lastKnown` и подписан на onChanged.
   Никогда не писать весь объект настроек снимком DOM.
5. **Хоткеи**: `event.code` (раскладко-независимо: KeyF = «а»!), обязательные
   гейты typing-context / модификаторы / repeat — и в роутере, И в любом
   отдельном listener'e (как dBlocker в role-faker).
6. **WebSocket-переподключение**: перед заменой сокета отвязать ВСЕ четыре
   хендлера старого (включая onopen!) и сделать полный teardown состояния
   (isConnected и пр.), иначе — залипшие статусы и вечный connecting.
7. **Симметрия жизненного цикла**: всё, что навесил enable(), снимает
   disable() — та же ссылка, тот же capture-флаг; хвостовые setTimeout —
   в именованных переменных и тоже гасятся.
8. **Формы данных матча** сверять с `legacy/match_314446.json`, а не с
   предположениями. Известное: `data.{players,votes,shots,checks}`; туры
   голосования `num: 0` = **выставление** (заявки кандидатур в речах) /
   `1` = **голосование** (основное) / `2` = **повторное голосование**
   (перестрелка ничейных кандидатов после ничьей; метка UI «перегол.»).
   «**Подъём**» — это НЕ тур 2, а отдельный бюллетень «поднимаем всех?»
   (см. ниже); терминология уточнена владельцем 26.07.2026 (до этого тур 2
   ошибочно назывался «подъёмом» и в 8.1.32-8.1.38 UI, и здесь).
   Это термины сообщества спортивной мафии — НЕ «исправлять».
   **Подъём может увести НЕСКОЛЬКИХ игроков сразу** («попил»): при чётном
   столе повторное голосование может повторить ничью — и если стол
   проголосовал за подъём, уходят ВСЕ ничейные кандидаты. Реальный пример:
   `polemicagame.com/match/598995`, день 4 (6 живых, 3:3 в обоих турах →
   ушли №4 и №5). Любая структура «ушедший = одно число» такой день выразить
   не может — только список.
   **Бюллетень «поднимаем всех?»** — это записи в votes БЕЗ поля num:
   `{"day":4,"voter":3,"candidate":1}`; `candidate: 1` = «за» (подтверждено
   владельцем, 8.1.38). Это НЕ голос за игрока №1! Любой код по votes обязан
   отделять такие записи (`num == null`), иначе `vote.num || 0` превращает их
   в ложные «выставления». Попил состоялся, если «за» СТРОГО больше, чем
   «против» — подтверждено владельцем (26.07.2026): «если нет или поровну —
   начинается ночь и все остаются за столом». Маркер «против» в данных пока
   не встречался; у матчей без бюллетеня ничья в подъёме считается уходом.
   Второй референсный JSON (попил + бюллетень): `docs/fixtures/match_598995.json`.
9. **Атрибут данных матча — `<Gamestats :game-data='...'>`** (26.07.2026 сайт
   переименовал его с `data-game`, и разбор молча сломался у всех — имя
   атрибута это внешний контракт, за ним надо следить). Значение — чистый
   JSON; парсить parse-first, декод HTML-энтити только фолбэком на исключение
   (слепой декод ломает URL с query-параметрами: `&quota=` → `"a=`).
   Заголовок X-Requested-With в match-data.ts — безвредная страховка (так
   запрашивает сам сайт), а не необходимость: в момент миграции наблюдалась
   выдача без данных, стабильно не воспроизводится.
   Роли: 0=дон, 1=мафия, 2=мирный, 3=шериф; `firstKilled` — это userId,
   НЕ позиция; guess бывает у нескольких игроков.
   Число дней НЕ фиксировано (может быть и 3, и 8+) — нигде не зашивать;
   `maxDay` считается из votes/shots/checks.
10. **Состояние фичи, переживающее выгрузку SW**, нельзя держать в модульной
    переменной background: service worker MV3 умирает через ~30с бездействия,
    то есть раньше любого будильника на минуту и дольше. Идентификаторы
    кодировать В ИМЕНИ alarm/notification (кейс queue-guard, 8.1.43), а
    достоверность состояния вкладки спрашивать у самой вкладки
    (`tabs.sendMessage`): `tab.active` истинно и у свёрнутого ОКНА.
11. **Миграции storage** — атомарно (данные+флаг одним `set`), флаг
    per-device в local, sync-копию заметок не удалять (мост для вторых
    устройств). Разовые чистки — в `runUpgradeMigrations()`
    (background/index.ts) под собственным флагом.
12. При «оживлении» настройки, которую старый попап писал, но никто не
    читал, — обязательна разовая миграция: у всех активных пользователей в
    storage лежит бессмысленное старое значение (кейс
    twitch_floating_panel_enabled, 8.1.23→8.1.24). Смена ДЕФОЛТА миграцией не
    является: у уже настроивших значение лежит в storage и не изменится
    (кейс role_marker_enabled true→false, 8.1.43).

### Что попадает в файл лога (решения владельца, 02.08.2026)

Логи включены по умолчанию (`debug_logging_enabled: true`) — это единственный
способ разобрать жалобу «перестало работать»: просить пользователя включить
запись и воспроизвести проблему заново получается далеко не всегда.

- В файл идёт только `info` и выше (`bufferLevel` фиксирован, не управляется
  страницей). `debug` не персистится нигде.
- **Чистка секретов — на стоке** (`record()`), а не на вызывающих: строка
  безопасна независимо от того, вспомнил ли о `redactSecrets` автор.
- Адрес OBS пишется как схема+хост+порт (`safeEndpoint`): в `obs_host` бывает
  `ws://user:pass@host`. Причина обрыва — наша категория (`closeCategory`), а
  не текст от сервера: его содержимое мы не контролируем.
- **Имена сцен OBS и название твич-канала пишутся как есть** — осознанно.
  Аудит наблюдаемости предлагал заменить их на «задано/пусто», но без имени
  сцены жалоба «переключилось не туда» неразбираема, а лог принадлежит самому
  пользователю и отправляет его он сам.
- Ники игроков и тексты заметок в лог НЕ пишем.
- Файл обязан сообщать о своей неполноте: при отказе `storage.local` в шапке
  `complete: NO`, в конце — синтетическая error-строка, в попапе — тост.

## 7. Как аудитить этот проект

Проверенная методика (4 итерации, ~50 подтверждённых находок):

1. Запускай 5–7 узкоспециализированных субагентов ПАРАЛЛЕЛЬНО, каждому —
   свой срез (готовые промты: `docs/audit-prompts.md`).
2. Каждому агенту давай список УЖЕ ИЗВЕСТНЫХ находок («не повторяй») — иначе
   половина отчёта будет пересказом.
3. Требуй: файл:строка, конкретный сценарий пользователя, серьёзность, и
   ОБЯЗАТЕЛЬНО раздел «проверено и чисто» (отсутствие находок в области —
   тоже результат).
4. **Проверяй громкие находки сам, прежде чем чинить.** Агенты ошибаются:
   «рассинхрон формы payload» в match-stats был опровергнут реальным JSON
   (`legacy/match_314446.json`), а «XSS в баннере обновления» — чтением кода
   (там textContent). И наоборот: «аутентификация OBS не работала никогда»
   подтвердилась.
5. После каждой волны фиксов — отдельный агент на ревью СВЕЖЕГО диффа
   (регрессии находились в каждом релизе: acceptScanTimer, twitch onopen,
   завис connecting, регрессия twitch_floating_panel_enabled) и отдельный
   агент на «путь обновления» (что случится у живых пользователей со старым
   storage).
6. Сверка бэклога отдельным агентом: «проверь по коду, что из списка ещё
   открыто» — не верь списку на слово.
