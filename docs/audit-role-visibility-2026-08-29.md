## Вердикт

Обнаружено 6 блокеров, 2 высоких и 3 средних дефекта. Главный общий класс:
глобальные latch/snapshot относятся к старому DOM-узлу, но трактуются как
состояние текущей роли.

## Находки

### 1. BLOCKER: OBS не скрывает роль после Vue-перерисовки в той же фазе

Код: `src/content/panels/obs-panel.ts:519-529,543-578,596-607,1006-1018,1179-1208`.

Сценарий: OBS-автомод скрыл роль днём → Vue заменил плитку без смены фазы →
новый узел не получил inline-пин → настоящая роль видна в эфире.

Направление: **в эфир**.

Доказательство: `lastAppliedRoleVisibility = "hidden"` относится к старому
элементу. Мутации вне `phaseScope` игнорируются, повторная детекция возвращает
раньше применения при `day === day`, а явный schedule также останавливается на
stale latch.

Тот же дефект воспроизводится при SPA-выходе и возврате в комнату в той же фазе.

### 2. BLOCKER: persisted latch подавляет retry после F5

Код: `src/content/panels/obs-panel.ts:477-508,537-540,596-607,1012-1018`.

Сценарий: F5 днём → сохранено `lastAppliedRoleVisibility: "hidden"` → OBS
восстанавливает latch до появления ролевого DOM → `applyRoleVisibility()`
возвращает `false` → retry видит уже `"hidden"` и ничего не делает → роль
монтируется видимой на дневной сцене.

Направление: **в эфир**.

Доказательство: присваивание выполняется на `obs-panel.ts:503`, применение на
`:505`, а вызванный после неудачи schedule немедленно возвращает на `:605-607`.

`tests/invariants/obs-role-latch.test.ts` этот обход не видит: OP-1 проверяется
только внутри `hideRoleBeforeDaySceneSwitch()`.

### 3. BLOCKER: Vue-перерисовка собственной роли снимает подмену F

Код: `src/content/features/role-faker.ts:84-100,161-171,186-201,205-237`.

Сценарий: стример нажал F → показана фальшивая роль → Vue заменил узел
собственной роли → новый узел показывает настоящую роль → `isFaked` и D-blocker
остаются активными, но подмена не наносится повторно.

Направление: **в эфир**.

Доказательство: observer повторно скрывает только чужие роли и явно исключает
собственную. `changeRole()` для нового узла больше не вызывается.

### 4. BLOCKER: D-blocker срабатывает после auto-start

Код: `src/content/index.ts:52-59`, `src/core/keyboard.ts:67-74`,
`src/content/features/role-faker.ts:84-100,175-202`,
`src/content/features/auto-start.ts:1315-1328`.

Сценарий: авто-скрытие держит CSS → стример нажимает F → затем D, ожидая
заблокированное действие → ранний keyboard-router снимает CSS на
`auto-start.ts:1323` → поздний dBlocker блокирует только сайт, но не уже
выполненную запись → E возвращает настоящую роль при снятом CSS.

Результат: настоящая роль видна в эфире.

Направление: **в эфир**.

Причина порядка: router устанавливается при auto-start раньше, dBlocker
добавляется только после успешного F. `stopPropagation()` не отменяет уже
вызванный listener.

### 5. BLOCKER: попап уничтожает независимую автосмену ролей

Код: `src/static/popup.html:442-446`,
`src/popup/index.ts:1411-1416,1617-1619,1875-1882`,
`src/content/features/auto-start.ts:1467-1472,1487-1492`.

Сценарий: стример хочет оставить «днём скрыто, ночью показано», но выключает
только «Автоотключение» → попап принудительно снимает и сохраняет автосмену как
`false` → content снимает CSS и показывает роль днём.

Направление: **в эфир**.

Это противоречит тексту UI, production-комментарию и исполняемому тесту
`tests/unit/auto-start-accept.test.ts:288-320`, которые утверждают, что
автосмена работает самостоятельно.

### 6. BLOCKER: одинаковые назначения V/D/F/E вытесняют защитный хоткей

Код: `src/popup/index.ts:1212-1225,1257-1268,1599-1602`,
`src/core/keyboard.ts:131-139`, `src/content/features/role-faker.ts:255-282`.

Сценарий: D и F/E назначены на один код → последний handler заменяет скрытие в
`Map` → стример нажимает отображаемую клавишу скрытия → выполняется fake/reset,
а роль остаётся видимой.

Направление: **в эфир**.

Отдельно опасен `reset = KeyD`: reset сначала восстанавливает настоящий
`#stop`/href и снимает dBlocker, после чего тот же event доходит до нативного D
сайта и может показать настоящую роль.

Фикс SEAM-07 не закрывает это: он не позволяет двум кнопкам одновременно
захватить один keydown, но последовательное назначение одинаковых кодов
разрешено.

### 7. HIGH: OBS-пин и V оставляют собственную роль с display:none

Код: `src/content/panels/obs-panel.ts:543-574`,
`src/content/features/auto-start.ts:442-499,693-735`.

Сценарий: OBS днём скрыл роль inline → V снимает слои → auto-start принимает
чужие `hidden/0` за собственный original snapshot → при отпускании пишет
дополнительно `display:none` → ночью OBS возвращает только
`visibility/opacity`, но не `display`.

Направление: **от игрока**.

Результат: собственная роль остаётся скрытой через всю ночь до F5 или
переключения настроек. Нормальный D `display:none` не исправляет.

Та же конечная поломка возникает, если выключить OBS-автомод, пока V
удерживается: OBS сначала восстанавливает стили, затем `stopPeek()` снова
записывает скрытие, уже без владельца, который мог бы его снять.

### 8. HIGH: role-faker не восстанавливает чужой узел, созданный во время F

Код: `src/content/features/role-faker.ts:149-180,240-247`.

Сценарий: F активен → Vue создаёт новый узел роли напарника или проверки →
observer ставит ему `display:none`, но не добавляет его в `originalRoles` →
E/disable восстанавливают только старые узлы.

Направление: **от игрока**.

Новый узел остаётся скрытым до следующей перерисовки сайта или F5.

### 9. MEDIUM: ночной показ считается успешным на временном состоянии V/F

Код: `src/content/features/auto-start.ts:826-877,988-1026`,
`src/content/features/role-faker.ts:186-195`.

Сценарий V: нативно скрытая роль показана для peek → наступает ночь →
одноразовый night-show видит роль показанной и обнуляет retries → отпускание V
возвращает `#stop` → повторного night-show нет.

Сценарий F: F заменил сохранённый `#stop` фальшивой иконкой → night-show считает
показ успешным → E возвращает `#stop` → стабильная фаза не запускает новую
попытку.

Направление: **от игрока**.

Обычный D восстанавливает роль, поэтому серьёзность средняя.

### 10. MEDIUM: D во время V всё равно доходит до сайта

Код: `src/content/features/auto-start.ts:1302-1311,1387`.

Сценарий: V удерживается → расширение пишет в лог, что D «не действует», но
возвращает без `stopPropagation()` → нативный D сайта меняет `#stop` → после
отпускания V роль может остаться нативно скрытой.

Направление: **от игрока**.

Текущий unit-тест вызывает handler напрямую без события и потому не проверяет
распространение до сайта.

### 11. MEDIUM: выключение под дневным OBS-пином может нативно спрятать роль

Код: `src/content/features/auto-start.ts:545-579,1487-1492,1516-1523`,
`src/content/panels/obs-panel.ts:1218-1225`, `src/core/feature.ts:96-127`.

Сценарий: CSS auto-hide и OBS скрывают роль днём → выключается auto-hide или
мастер-выключатель → `setRoleVisibility(true)` видит чужой OBS inline-hide и
при `trackedRolesVisible=false` отправляет нативный D → OBS позже снимает
inline-пин, но сайт остаётся на `#stop`.

Направление: **от игрока**.

Исправляется ручным D или F5, поэтому не высокая.

## Карта силы

| Писатель | Запись | Область | Сила | Переживает Vue replacement |
|---|---|---|---|---|
| auto-start CSS | `visibility`, `opacity`, `pointer-events` | все роли | stylesheet `!important` | Да |
| OBS | `visibility`, `opacity` | своя роль | inline `!important` | Нет |
| auto-start inline/peek | `display`, `visibility`, `opacity`, `pointer-events` | своя роль | обычный inline | Нет |
| role-faker | `display:none` | чужие роли | обычный inline | Observer повторяет, но snapshot теряется |
| role-faker fake | SVG href, tooltip, data-атрибуты | своя роль | DOM-атрибуты | Нет |
| сайт | `#stop`, Vue-state и обычные стили | своя роль | ниже наших `!important` | Новый узел стирает extension-inline |

Inline `!important` OBS перебивает CSS `!important`, но `display:none`
auto-start/role-faker скрывает элемент независимо от
`visibility:visible !important`.

## Коллизии клавиш

Порядок регистрации при загрузке: `V → D → F → E`. Последний handler для
одинакового кода побеждает.

| Одинаковая пара | Победитель при загрузке | Победитель при одновременном live-update |
|---|---|---|
| V / D | D | V |
| V / F | F | F |
| V / E | E | E |
| D / F | F | F |
| D / E | E | E |
| F / E | E | E |

Победитель V/D дополнительно зависит от того, какую клавишу изменили
последней. Если победившую фичу затем выключить, вытесненный handler не
восстанавливается.

Repeat, `keyup`, blur, hidden-tab, typing-context и Ctrl/Meta/Alt для разных
стандартных клавиш проверены и чисты. Потерянный `keyup` fail-closed: peek
снимается на blur/visibility change.

## Lifecycle

- OBS setting off: известные таймерные и await-хвосты закрыты; исключение
  только active V, находка №7.
- Feature disable: таймеры OBS чисты; cross-feature порядок создаёт №11.
- SPA: auto-start CSS переживает переход; OBS inline-пин не переживает,
  находка №1.
- F5: auto-start стартует заново; OBS persisted restore имеет блокер №2.
- Обновление расширения: DOM-пины остаются. Chrome сохраняет старый DOM-код и
  показывает orphan-баннер; подтверждённой новой утечки сверх перечисленных
  interleaving не найдено.
- `obs_disconnected`: текущий скрывающий пин не снимается, pending role work
  сбрасывается; прямой утечки роли не найдено.
- Две вкладки одной комнаты: DOM-пины вкладок независимы. Общий persisted state
  пишется без ownership-гейта, но детерминированную утечку при одинаковом живом
  состоянии комнаты доказать не удалось.
- Обычные переходы day/night без V/F и без replacement чисты.
