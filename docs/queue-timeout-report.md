# Почему игрока выкидывает из очереди поиска в фоновой вкладке

Замер: 27.07.2026, сокет очереди `wss://game.polemicagame.com/socket.io/`,
инструмент — «Диагностика подключения» расширения Polemica Notes
(перехват WebSocket на прототипе + контроль дрейфа таймеров).

## Итог одной строкой

**Соединение рвётся через ~1 мин 40 сек после сворачивания вкладки** (не через
5 минут), потому что браузер душит таймеры фоновой вкладки, клиентский ping
socket.io не успевает уйти вовремя, и сервер закрывает сессию по своему
таймауту. Переподключения не происходит **никогда** — даже после возврата на
вкладку.

## Хронология (t — от загрузки страницы)

| Время | Событие |
|---|---|
| +1.9s | `WS OPEN` + handshake: `pingInterval: 25000, pingTimeout: 20000` |
| +2.1s | `start_game_search`, дальше `check_if_user_is_in_game` каждые ~7s |
| +24.4s | **вкладка свёрнута** (`visibility hidden`) |
| +27.5s / +54.5s / +80.5s | `ping->` и сразу `pong<-` — связь живая |
| +84s | дрейф таймера +1s (лёгкий троттлинг, безвреден) |
| +105.5s | **дрейф таймера +16s** — троттлинг углубился |
| ~+105.5s | ping ДОЛЖЕН был уйти (25s после предыдущего) — **не ушёл** |
| **+125.7s** | **`WS CLOSE code=1005 clean=true`** — сервер закрыл сессию |
| далее | дрейф +55s (таймеры раз в минуту), ни одной попытки реконнекта |
| +392s | возврат на вкладку — сокет по-прежнему мёртв, поиск не восстановлен |

## Механика

1. У сервера `pingInterval = 25s`, `pingTimeout = 20s` → клиент обязан прислать
   ping не реже, чем раз в **45 секунд**, иначе сессия закрывается.
2. Ping в engine.io v3 инициирует **клиент**, по `setTimeout`. В фоновой
   вкладке браузер растягивает таймеры: сначала на ~1s, примерно через
   полторы минуты — до раза в минуту (в логе: дрейф +1s → +16s → +55s).
3. Последний ping ушёл в +80.5s. Следующий был должен в ~+105.5s, но таймер к
   тому моменту уже отставал на 16s и продолжал деградировать.
4. Сервер закрыл соединение в +125.7s — **ровно 45.2s после последнего ping**,
   то есть строго по своему `pingInterval + pingTimeout`. Совпадение до
   десятых долей секунды: причина именно эта, а не сеть.
5. `reconnection: false` (см. создание сокета в `bundle/game-search.js`) —
   после разрыва клиент не пытается вернуться, и игрок молча выпадает из
   очереди. Возврат на вкладку тоже ничего не восстанавливает.

## Что можно сделать на стороне сайта

1. **Лучший вариант — server-initiated ping** (socket.io v4 / engine.io v4):
   там ping шлёт сервер, а клиент отвечает из обработчика входящего
   сообщения. Входящие сообщения доставляются и в фоновой вкладке без
   задержек, поэтому класс проблемы исчезает целиком.
2. **Дёшево и сразу** — включить `reconnection: true` для сокета очереди.
   Механизм восстановления поиска у клиента уже есть: ветка, которая при
   наличии `timeInSearch` в состоянии возвращает игрока в очередь после
   переподключения. Сейчас она просто недостижима.
3. **Смягчение** — поднять `pingTimeout` до значения больше типичного шага
   throttling (60s+), чтобы одного пропущенного тика не хватало для разрыва.

## Что может расширение

Отменить троттлинг браузера расширение не может. Максимум — предупреждать:
при уходе страницы поиска в фон показывать уведомление за ~60s до вероятного
разрыва. Не лечит причину, но избавляет от молчаливого вылета.
