## Найденные баги

> **Статус на 02.08.2026: все десять исправлены**, `test.todo` больше нет —
> каждая проверка стала настоящей и падает на коде до правки. Набор вырос до
> 195 проверок. Ход работы и что изменилось сверх списка — в разделе
> «Исправление 02.08.2026» ниже.

### 1. `isSafeNoteKey` доверяет compile-time типу

**Воспроизведение:** вызвать `isSafeNoteKey(["Alice"] as any)` — массив проходит;
`null`/`undefined` бросают на `.length`; строка длиннее 200 символов принимается,
хотя storage/import limit равен 200.

**Риск:** crafted backup или повреждённое persisted state обходят ожидаемый
runtime boundary. Часть callers отдельно проверяет длину, но helper не выполняет
собственный заявленный safety contract.

### 2. `mergeNotes` зависит от порядка mixed backup

**Воспроизведение:** incoming map содержит сначала `Alice`, затем `u:7` с
`nick: "Alice"`. Ник-ключ создаётся до появления id в индексе и остаётся дублем.
Обратный порядок даёт одну запись.

### 3. Base id keys не канонизируются

**Воспроизведение:** base содержит `u:007`, incoming — `u:7`. Канонизируется
только incoming, поэтому в результате остаются два ключа одного пользователя.

### 4. Merge может потерять непустое поле

**Воспроизведение:** более новая incoming запись имеет `text: ""`, а старая —
непустой text: новый пустой text побеждает. В обратном направлении timestamp
может оставить новую запись без color и проигнорировать color из более старого
аргумента. Desired property «не терять непустое» сейчас не выполняется
симметрично.

### 5. Color index не защищён от старого мусора

**Воспроизведение:** `buildNickColorIndex({"u:1": {text:"", timestamp:1,
nick:123, nickColor:"#fff"} as any})` бросает на `toLowerCase`. `u:001` также
не находится по id `1`, потому что index не канонизирует id key.

### 6. Pretty JSON обходит redaction

**Воспроизведение:** `redactSecrets('"token" : "abcdef"')` сохраняет секрет.
Regex допускает максимум четыре separator characters, а обычная pretty-запись
между key и value содержит пять.

### 7. Countdown принимает невозможное время

**Воспроизведение:** `parseCountdownSeconds("1:60") === 120`; строка с минутами
из трёх цифр может матчиться по внутреннему двухзначному фрагменту. При смене
формата сайта это искажает решение requeue.

### 8. В `auto-start` остался wildcard scan

`src/content/features/auto-start.ts` всё ещё выполняет один
`querySelectorAll("*")` для fallback поиска стартовой кнопки. Это нарушает
§4.1/§4.2 и может дорого сканировать большой modal subtree.

### 9. Неполный отдельный hotkey gate

`role-faker` проверяет code/typing/modifiers, но не `e.repeat` в отдельном
keydown blocker. Зажатая клавиша нарушает буквальный инвариант §4.5.

### 10. Два lifecycle tail

- `role-marker`: `setTimeout(0)` может прикрепить outside listeners уже после
  `disable()`, потому что callback не отменяется.
- `auto-start`: отложенный webcam click не имеет teardown handle и может
  выстрелить после выключения фичи.

## Исправление 02.08.2026

Все десять закрыты, `test.todo` снят; 195 проверок зелёные. Как исправляли:

| № | Исправление |
|---|---|
| 1 | `isSafeNoteKey(key: unknown): key is string` — typeof-гард, пустая строка, лимит `MAX_NOTE_KEY`. Отдельный внутренний `isPlainKey` без лимита длины: уже лежащий на диске длинный ключ выбрасывать при слиянии нельзя. |
| 2 | Входящие записи нормализуются в список ДО слияния, id-ключи попадают в индекс ников раньше ник-ключей. |
| 3 | Ключи базы тоже канонизируются, коллизии `u:007`/`u:7` сводятся в одну запись. |
| 4 | Новый `combineNotes`: побеждает более свежая, но каждое ПУСТОЕ поле победителя добирается из проигравшей — симметрично, независимо от порядка аргументов. |
| 5 | `buildNickColorIndex` канонизирует id-ключи и переживает `nick`, который не строка (раньше одна битая запись роняла индекс целиком — то есть цвета пропадали разом у всех). |
| 6 | В `SECRET_RE` поднят лимит разделителей до восьми (перенос строки в них НЕ входит). |
| 7 | `parseCountdownSeconds` — границы по цифрам и `[0-5]\d`; непонятая строка не перезаписывает последнее прочитанное значение отсчёта. |
| 8 | `querySelectorAll("*")` заменён списком кликабельных кандидатов + deepest-only дедуп + гейт видимости. |
| 9 | Гейты вынесены в экспортируемый `shouldSwallowRoleKey`; `e.repeat` здесь осознанно инвертирован (подавление обязано быть непрерывным, иначе сайт покажет настоящую роль посреди подмены) и закреплён тестом поведения в jsdom. |
| 10 | `armTimer` в role-marker и `webcamClickTimer` в auto-start — именованные, гасятся в `closeMenu`/`disableAutoAccept`. |

Adversarial review прошло в два раунда и нашло сверх этого списка 12 находок;
исправлены все, кроме одной, оставленной осознанно. Существенное:

- **Файл перезаписывал `nick` (блокер второго раунда).** `nick` — не текст
  пользователя, а связка идентичности: по нему ищется id-запись игрока,
  строится индекс цветов и дедуп ник-ключей. Переписанный устаревшим ником из
  файла, он рвал связку — повторный импорт того же файла заводил ник-ключ
  заново (дубль, невидимый при чтении id-first), цвет переставал находиться по
  нику, а модалка заметки открывалась пустой. Теперь ник существующей записи
  файлом не переписывается; слияние идемпотентно (свойство «повторный импорт
  ничего не меняет», 300 прогонов).
- **Мост из storage.sync стал бы вечным источником воскрешения.** Снимок sync
  заморожен с 8.1.29, но правило «непустое побеждает пустое» позволяло ему
  добирать поля в живые записи — молча, при первом запуске на каждом новом
  устройстве, возвращая снятую метку прямо в игру. У `mergeNotes` появился
  режим `{ onlyNew }`: мост вносит только отсутствующие ключи и не трогает
  существующие записи.
- **Слияние падало на `null` в карте базы** — повреждённое хранилище роняло
  импорт целиком, а миграция из sync повторялась бы вечно (флаг не выставлялся).
- **Поглощение ник-ключа id-записью склеивало заметки о РАЗНЫХ игроках**: ник на
  сайте освобождается и достаётся другому человеку. Механизм убран; редирект
  ник-ключа в id-запись теперь происходит, только если такого ник-ключа в карте
  ещё нет. Ни одна ветка слияния больше не делает `delete`.
- **`obs_password` — наш собственный ключ — не вычищался из логов вообще**:
  `\b` не срабатывает после подчёркивания. Добавлен префикс `(?:[a-z0-9]+[_-])?`.
- Ники, совпадающие с методами `Object.prototype` (`toString`, `valueOf`),
  давали битые записи → везде `Object.hasOwn`.
- Счётчик `replaced` больше не растёт от смены представления легаси-строки;
  формулировка подтверждения импорта исправлена на «изменит … данными из файла».
- Архитектурные проверки, ставшие тавтологией или регэкспом по всему файлу,
  переписаны: поведение в jsdom для §4.5, AST-хелпер `functionBody` для §4.7.

**Оставлено осознанно.** Правило «непустое побеждает пустое» делает невозможным
распространение ОСОЗНАННОГО стирания поля: импорт старого бэкапа воскресит
текст или метку, снятые на другом устройстве. Признак «поле очищено намеренно»
(tombstone) — это смена формата хранилища, отдельная задача. Выбор в пользу
сохранности данных: молчаливая потеря заметки хуже, чем воскресшая метка после
импорта, который пользователь запустил сам.

## Что не покрыто

- Реальный Firefox 121 event-page/WebSocket idle и Chrome 116 SW termination:
  platform premise нельзя доказать jsdom/fake timers.
- Store/XPI update с уже открытой игрой, session restore ordering и sleep-delayed
  alarms требуют установленного расширения в настоящих браузерах.
- OBS Studio, две реальные игровые вкладки, камера/GPU и main-thread profile.
- Живые socket.io queue operations намеренно не выполняются: им нужны
  `authKey`/session, и тест мог бы поставить аккаунт в настоящую очередь.
- Contract parser проверяет class/string/API presence, но не доказывает DOM
  nesting, visibility и semantic target каждого generic selector.
- Lifecycle static check — эвристика: DOM-owned handlers учитываются allowlist;
  semantic teardown дополнительно остаётся предметом review.
- Полный round-trip popup backup и match renderer пока не вынесены в чистые
  planners; их тест потребовал бы более крупного production refactor.
